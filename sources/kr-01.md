# MCP server - Kraken docs

**Official source** · Kraken · official-doc · retrieved 2026-11-19 · [open the original](https://docs.kraken.com/home/mcp)

## Summary

Kraken's CLI ships a local MCP server, kraken-mcp, over stdio, serving 152 of the CLI's commands as MCP tools. Service flags (-s) choose which command groups are exposed: market, account, paper, workspace, futures-paper, feedback, trade, futures, earn, funding, subaccount, auth, or all. Kraken's quickstart set (market,paper,feedback) needs no credentials, and no tool in it can trade live or move funds; with no -s flag the server exposes market, account, paper, workspace and feedback. Tools marked dangerous need user approval for every call through MCP elicitation; --allow-dangerous turns the gate off. The server runs locally and is not a network service. Authentication is by API key and secret as environment variables or a stored key from kraken auth login or kraken setup. Client setup is documented for Claude Code (plugin or claude mcp add), Claude Desktop, Cursor, VS Code (Copilot), Windsurf, Gemini CLI and other MCP clients.

## Short quotes

> This starts the server with market data, paper trading, and the feedback tool, which uploads the text you give it to Kraken. No credentials are required, and no tool can trade live or move funds.

> Tools marked dangerous (order placement, withdrawals, transfers, workspace promotion) need your approval for every call. The server asks you through MCP elicitation and runs the call only if you approve.

> The MCP server runs locally over stdio and is not exposed as a network service

> Set position size limits and pair allowlists at the API key level on Kraken’s settings page
