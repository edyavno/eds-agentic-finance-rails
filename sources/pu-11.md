# Enforce preflight and user confirmation on every order — 0.11.0 (pull request 19)

**Official source** · Public.com (GitHub) · repo · retrieved 2026-11-18 · [open the original](https://github.com/PublicDotCom/publicdotcom-mcp-server/pull/19)

## Summary

Merged pull request 19 on Public's official MCP server (2026-11-17). Order tools now pass through a server-side order gate: optional per-order quantity and value limits set in environment variables the model cannot change from the chat, a preflight of the exact order (nothing is sent if the preflight fails), and user confirmation through MCP elicitation. Confirmation mode is auto by default, and can be set to required or off; limits and preflight apply in every mode. cancel_order is not gated. The PR says the same changes are being ported to the hosted server's develop branch for testing, and that nothing had yet run against a real API when it was written. Whether the hosted server has these changes is unknown.

## Short quotes

> every order tool now goes through an order gate before anything reaches the trading API.

> Limits come from env vars, which the model can't change from the chat. All are off by default.

> If the preflight fails, nothing is sent.

> The same changes are being ported to the hosted server's `develop` branch for that testing.
