# Human-in-the-loop patterns

## 1. Prefer broker-side approval when it exists

If the broker can hold the order until a person confirms it, use that. Examples: Webull Cloud MCP,[^wb-07] IBKR AI Integration,[^ib-07] and Robinhood with Trade approvals on.[^rh-04] A client-side prompt can be skipped by a different client; Coinbase documents two clients behaving differently against the same server.[^cb-01]

## 2. Cap the blast radius

Give the agent its own funded account, portfolio or partition, and fund it with what you accept losing.[^rh-10][^cb-03][^ib-06]

## 3. Show the full order before asking

IBKR's example prompt asks the agent to show account, side, quantity, order type, limit price, estimated value and available cash before creating an instruction.[^ib-06] Public documents a preflight that shows estimated cost and buying-power impact before you confirm.[^pu-06]

## 4. A dry-run token is not approval

tastytrade's MCP requires a single-use, 60-second confirmation token from a dry run before an order tool acts, and states plainly that the token is not human approval because the same agent mints and redeems it.[^tt-01]

## 5. Where the broker has no approval step

For Alpaca or a local Webull server, put the approval in your own client: require a person to confirm a rendered order summary, keep limits outside the agent's reach, and test on paper or sandbox first.[^al-05][^al-01][^wb-03]
